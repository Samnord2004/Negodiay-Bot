# 🏴‍☠️ Руководство: Локальный запуск на Mac OS / Windows и туннелирование

Это руководство объясняет, как запустить портал команды «Негодяи» локально на вашем компьютере (**Mac OS** или **Windows**) на безопасном свободном порту (например, **8090**, **7777**, **8000** или **4000**), избегая конфликтов с портами **3000** и **5000**, а также как открыть доступ сокомандникам через интернет с помощью туннелей.

---

## ⚠️ Почему избегаем портов 3000 и 5000?

- **Порт 5000 на macOS**: Начиная с macOS Monterey, порт `5000` по умолчанию занят системной службой **AirPlay Receiver** (`ControlCenter`). Попытка запустить сервер на 5000 приводит к ошибке `EADDRINUSE`.
- **Порт 3000**: Часто занят фоновыми серверами разработки, Docker-контейнерами или другими сервисами.
- **Рекомендуемые порты по умолчанию**: `8090`, `7777`, `8888`, `4000`.

---

## 1. Быстрый старт на Mac OS / Linux

### Вариант А. Через готовый скрипт (в 1 команду)
В терминале перейдите в папку проекта:
```bash
# Запуск на порту 8090 по умолчанию:
./start-local.sh

# Или укажите любой другой порт (например, 7777):
./start-local.sh 7777
```
*Скрипт сам проверит Node.js, при необходимости выполнит `npm install` и `npm run build`, а затем запустит сервер.*

### Вариант Б. Через стандартный npm / node
```bash
# 1. Установка зависимостей (один раз)
npm install

# 2. Сборка (один раз или после изменений)
npm run build

# 3. Запуск на порту 8090:
npm run start:local

# Либо запуск на произвольном порту с флагом --port:
node dist/server.cjs --port 7777
# Либо через переменную окружения PORT:
PORT=8090 node dist/server.cjs
```

## 2. Быстрый старт на Windows

### Вариант А. Через PowerShell
Откройте PowerShell в папке проекта:
```powershell
# Запуск на порту 8090 по умолчанию:
.\start-local.ps1

# Или с указанием порта:
.\start-local.ps1 -Port 7777
```

### Вариант Б. Через командную строку Windows (CMD)
```cmd
start-local.bat
REM Или с указанием порта:
start-local.bat 7777
```

### Вариант В. Через npm
```cmd
npm install
npm run build
npm run start:local
```

## 3. Туннелирование в интернет (доступ для команды)

Чтобы участники команды могли заходить на портал с телефонов или других компьютеров без статического белого IP, запустите в **соседнем окне терминала** любую из утилит туннелирования:

### 🌟 Вариант 1. Cloudflare Tunnel (Рекомендуется)
*Бесплатно, без регистрации, без лимитов скорости, полная поддержка WebSocket (покер работает сразу).*
```bash
npx cloudflared tunnel --url http://localhost:8090
```
Или через команду в проекте:
```bash
npm run tunnel:cloudflared
```
*В консоли появится публичная ссылка вида `https://random-words.trycloudflare.com`. Отправьте её сокомандникам!*

---

### 🌐 Вариант 2. Localtunnel (Запуск без установки)
*Работает сразу через `npx`, не требует регистрации.*
```bash
npx localtunnel --port 8090
```
Или:
```bash
npm run tunnel:localtunnel
```
*Вы получите публичный URL вида `https://cool-pirate-ship.loca.lt`.*

---

### ⚡ Вариант 3. Pinggy (Работает через обычный SSH)
*Не требует установки никаких программ ни на Mac, ни на Windows 10/11:*
```bash
ssh -p 443 -R0:localhost:8090 a.pinggy.io
```
*Выдаст HTTPS-ссылку прямо в окне терминала.*

---

### 🛡️ Вариант 4. ngrok
Если у вас установлен [ngrok](https://ngrok.com/):
```bash
ngrok http 8090
```

## 4. Как работают сетевые функции через туннель?

1. **Онлайн-Покер Негодяев (WebSocket)**:
   - Клиент подключается по `wss://<ваш-туннель>/ws/poker`.
   - Cloudflare Tunnel, ngrok и Pinggy автоматически поддерживают апгрейд WebSocket-соединений, поэтому мультиплеерный покер за общим столом работает без дополнительных настроек.
2. **Mortal Kombat 3 Netplay (WebRTC)**:
   - Создание и подключение к игровым комнатам работает через REST API сервера и peer-to-peer WebRTC.
3. **Сохранение данных (База данных)**:
   - Локально на вашем Mac или Windows не обязательно устанавливать PostgreSQL!
   - В архитектуре портала предусмотрен **Dual-Persistence**: все взносы фонда, истории, квесты, участники и сообщения чата автоматически сохраняются в локальный файл `data/app_storage.json`.
   - Если вы решите подключить PostgreSQL (например, локальный или облачный), просто задайте параметры в файле `.env` (`SQL_HOST`, `SQL_USER`, `SQL_PASSWORD`, `SQL_DB_NAME`).
